Decision API

Boundary checks one text before your application calls a model. Run it alongside your chatbot backend and send requests over loopback.

POST /v1/check

curl --fail-with-body http://127.0.0.1:8765/v1/check \
  -H 'Content-Type: application/json' \
  -d '{"text":"How should I prevent SQL injection?"}'

Send a nonempty JSON string in the text field. The whole encoded request may contain up to 65,536 bytes. A successful check returns HTTP 200 for either decision.

action
block if the score exceeds the frozen gateway threshold. Otherwise allow.
score
Highest injection score across overlapping input windows. Treat it as a ranking score.
threshold
Cutoff used for this decision. Let the service apply it at full precision.
model
Name of the detector that scored the text.
device
Local hardware used for inference.

Failure handling

400 means invalid input, 413 means the body exceeds the limit, and 415 requires JSON content. A request can wait up to 100 ms for the inference slot. If the worker is still busy, the service returns 503. On a timeout, malformed response, or any error, withhold the provider call. Offer a retry for temporary failures.

Policy and sources

The gateway chooses its cutoff against a 2% empirical benign-flag budget in each validation group. Security question titles and ordinary cheat-sheet passages serve as benign examples by source. Attack variants and documents are grouped before splitting. Your chatbot’s traffic may have a different error rate. The held-out audit groups were inspected during development; treat these results as an observed benchmark.

Deployment boundary

This service listens on the same machine as your application. Put authentication, TLS, and rate limits at your own application boundary before offering remote access. Inspect each untrusted passage and user message separately. The model has been evaluated on text inputs. Tools still need their own authorization checks.

Protect a chatbot

Place the decision in the backend that owns the provider credentials. Choose shadow mode to observe decisions or enforcement to stop flagged messages.

Start the local service

uv sync --locked
uv run python -m injclf.serve

Run these commands from the classifier checkout with the gateway encoder and classification head in artifacts/gateway and the matching gateway policy in results/gateway.json.

Observe traffic in shadow mode

import logging
from injclf.gateway import shadow_call

logging.basicConfig(level=logging.INFO)
reply = shadow_call(user_text, send_to_provider)

Shadow mode forwards every message after inspection, including flagged messages and requests that time out. Keep existing provider protections enabled. Count shadow allow, shadow block, and shadow inspection_error events from the injclf.gateway logger. Each event records only the outcome. Check the decisions against labeled traffic before enabling enforcement.

Enforce decisions on your provider call

from injclf.gateway import guarded_call

def reply(user_text, send_to_provider):
    try:
        return guarded_call(user_text, send_to_provider)
    except PermissionError:
        return "This message was flagged for review."

Pass your existing provider function as send_to_provider. The helper sends the original text only after an explicit allow. Map service errors to an unavailable response in your backend. The same HTTP contract works with a local model or a hosted provider.

Use the HTTP API from JavaScript

async function guardedReply(text, callModel) {
  const res = await fetch("http://127.0.0.1:8765/v1/check", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ text }),
    signal: AbortSignal.timeout(2000)
  });
  if (!res.ok) throw new Error("Inspection unavailable");
  const { action } = await res.json();
  if (action === "block") return "Flagged for review.";
  if (action !== "allow") throw new Error("Invalid decision");
  return callModel(text);
}

Handle retrieved passages

Check the user message before retrieval. Check each retrieved passage before adding it to model context. Drop blocked passages and keep source labels separate from model verdicts. If a check fails, stop the request before inference.
